## 1.6.7：兼容无独立加密字段的学校登录表单

用户确认 1.6.6 的学校页面验证已能登录，原生表单仍被“缺少密码加密字段”检查阻止。这个检查把之前桌面页面的 passwordEncrypt 字段错误地当成了所有学校模板的必要条件。

- 不再要求 HTTP 登录页存在 passwordEncrypt；填写可见账号/密码字段后调用学校自己的登录按钮，允许学校模板在原密码字段内或提交过程中自行处理密码。学校令牌、隐藏字段和处理算法不由 App 替换。
- 若表单实际具有独立 passwordEncrypt 字段，仍保留该字段的提交检查。学校校验阻止提交、未填写验证码、非 POST 或站外提交地址仍会停止原生提交。
- 修正提交触发页面跳转之后的回调竞态：过期提交回调不再把 submitted 状态重置为 false，避免干扰后续认证成功时的凭证保存。凭证仍须在确认认证成功后写入独立加密存储。

验证：156 项合成表单检查包含缺少独立加密字段、学校处理原密码字段、验证码和提交目标拦截；既有页面探测、登录状态与教务脚本回归通过。学校网页登录成功由用户反馈确认；本次原生登录和凭证保存仍待手机验证。

## 1.6.6：遵循学校真实 HTTP 认证回跳

手机 1.6.5 的实际记录显示：HTTPS 登录请求收到服务器返回的 HTTP 重定向，App 改写回 HTTPS，随后同一 HTTP 重定向再次出现。全过程未显示登录表单，后续脚本因此运行在空白或错误页面上。强制升级与学校实际认证链路冲突，是这份记录中已经确认的阻断因素。

- 移除认证 HTTP 重定向的强制升级和相关重复升级分支；由 WebView 正常继续学校的跳转，保留请求、会话和回跳参数。初始地址仍为 HTTPS，若学校返回 HTTP，则按其真实协议继续。
- Android 网络配置仅新增 authserver.jhun.edu.cn 这个确切域名的 HTTP 许可。全局明文限制保留，其他域名未开放，证书错误仍取消。
- 登录页面及表单目标接受该认证域名的默认 HTTP/HTTPS 端口，保留学校原始 POST action；继续检查登录路径、回跳白名单、非 GET 提交和学校 passwordEncrypt 字段。HTTP 表单缺少加密字段或提交时没有有效加密结果则阻止原生提交。
- 保留加密凭证存储、其他账号隔离、移动报修回跳和连接诊断。诊断 DOCUMENT=2 表示已显示 HTTP 认证表单，1 表示 HTTPS 表单，0 表示尚非有效登录表单。

传输限制：HTTP 页面没有 HTTPS 的传输保护，学校的页面密码加密不等同于 HTTPS。此次兼容遵循用户指定的学校 HTTP 登录链路，不应描述为全程 HTTPS 登录。

验证：135 项模拟登录检查、47 项 URL 策略、59 项导航流程、31 项诊断隐私、20 项文档探测和既有教务脚本检查通过。导航测试覆盖实际 HTTPS→HTTP→后勤 CAS→移动表单序列，配置检查确认 HTTP 仅限三个精确学校域名。仍待手机端登录成功验收。

## 1.6.5：内置浏览器兼容、页面时序与手机诊断

用户确认同一手机及网络下普通浏览器能够正常登录，但 App 仍报告重复跳转和当前页面不是 HTTPS 登录页。这说明之前的 URL 修改没有完成手机端问题的修复。

- 统一认证专用 WebView 从系统默认 UA 中去除 ; wv 与 Version/4.0 标记，保留系统实际 Chromium 版本及移动端信息。用于兼容可能对内置浏览器采取不同跳转的学校页面；UA 是否是本次根因尚未得到真机验证。其余教务 WebView 不受影响。
- 页面开始加载、重新加载及失败时立即撤销表单可用状态。新页面提交可见或完成加载后才允许执行登录适配。脚本回调携带本次页面与登录尝试编号，页面切换后的旧回调不再覆盖新的登录状态。
- 原生表单和失败页增加主题色“连接诊断”入口，显示实际 App/WebView 版本、最近 40 条跳转和错误码、实际 DOM 来源分类及登录表单是否存在。用户点击后可复制；不自动上传，也不落盘。
- 诊断只保留白名单站点和路径，去除全部 URL 查询、fragment 和 jsessionid。未知路径、来源被替换为固定分类，不记录账号、密码、Cookie、票据、页面正文或表单值。

验证：31 项 UA/诊断隐私检查、20 项页面状态探测检查、125 项登录表单检查、47 项 URL 策略、64 项导航与既有教务脚本回归通过。手机端问题仍需要安装后的行为或诊断记录验证；本版不能声称已经完成真实认证登录验收。

## 1.6.4：直连后勤 CAS 认证

- 根据用户提供的地址，将统一认证和报修入口改为 authserver 的 HTTPS 登录页，service 直接指向 http://hqfw.jhun.edu.cn/wsbx/login/cas#/wybx。移除入口中的服务大厅 login/appShow 中转。#/wybx 编码在 service 参数内部，不能成为认证页面自身的 fragment。
- Edge 实际观察：该地址显示学校统一认证表单，随后回跳到 http://hqfw.jhun.edu.cn/wsbx/#/wybx，页面标题为 403。App 在收到这个明确的目录回跳时打开用户指定的移动版 HTML 入口，保留 CAS 刚建立的会话；不扩大到其他 403 页面。
- 登录成功判断不再接受任意后勤域名页面；CAS 回调路径或目录不能被当作报修页面。观察到认证票据之后，还要抵达报修 HTML 页面才处理成功。

验证：125 项合成表单检查、47 项 URL 策略检查、64 项导航检查，以及已有教务脚本和查询解析检查。Edge 中这次后续打开移动版被客户端 ERR_BLOCKED_BY_CLIENT 拦截，尚未验证本次直连的移动表单最终成功；没有 Android 真机端到端验收。代码中的回跳修正不能代替真实登录验证。

## 1.6.3：修正认证回跳误判

用户截图显示应用主动报出 HTTP/HTTPS 循环和表单不支持，而非学校返回密码错误。旧导航保护的 upgradeOnce 只要发现 HTTPS 路径曾加载过就拒绝第一次 HTTP 回跳；key 又丢弃全部查询参数，把不同 service/execution 当成同一次请求。

- 第一次升级同一认证请求允许继续，仅同一请求再次升级才触发循环保护。保留 service、execution、renew 等实际参数，只忽略票据、nonce、timestamp 与缓存扰动参数；不同大厅服务回跳不再混为一谈。
- HTTPS 认证页内，同一认证站点的 HTTP 表单 action 转为 HTTPS，保留完整回跳及表单参数。页面可见和加载完成时均准备表单，原生与学校页面验证入口一起适配。跨站、非默认端口、非 POST 或不允许的嵌套 service 仍拒绝。
- 支持 CAS 登录 Servlet 的合法 ;jsessionid 路径；不放宽站点、协议和其他路径限制。直接 HTTP 密码 POST 仍阻断，错误提示与实际重复导航分开。

验证：117 项模拟表单检查、64 项导航检查、36 项 URL 策略检查通过，包含先访问 HTTPS 再遇到首次 HTTP 回跳、不同 service/execution、实际重复升级、HTTP 表单安全转为 HTTPS及站外回跳拦截。尚未连接 Android 真机，不能把代码回归检查等同于真实账号登录成功。

## 1.6.2：原生统一认证提交等待修复

- 原生登录不再等待 WebView 的 onPageFinished。DOM 解析结束后直接检查学校表单，因此图片或其他资源未加载完成不会一直阻挡填写与提交。
- 点击登录立即收起键盘，按钮显示连接、准备表单、提交和验证阶段。脚本异常与无效回调返回明确错误，失败弹出提示并滚动到操作区域。
- 普通重试重新加载认证页，保留认证会话，不再等待清空 Cookie 的串行回调；主动切换账号和清除凭证仍执行独立会话清理。
- 使用学校自身的表单提交处理；观察 submit 事件，检查实际 passwordEncrypt 字段是否已由学校处理，尚未加密时阻止提交并等待，避免发送空或明文替代的密码字段。网页按钮未触发表单提交或被学校校验阻止时明确提示。
- 包含 1.6.1 的重复跳转保护、登录状态识别、重复成功回调保护和报修移动版切换，以及上一轮最终构建中断后未进入旧 APK 的重试修复。

验证：95 项合成凭证表单检查覆盖 DOM interactive 而非 load 完成、未触发提交、提交被取消、缺少加密结果、明文结果拦截和字段隔离。大厅识别、URL 策略和导航检查沿用 1.6.1。没有连接的 Android 测试设备；尚未完成手机原生输入到学校认证成功的端到端验证。

## 1.6.1：统一认证跳转与报修移动版修复

- 按已连接的 Edge 实际页面适配：认证表单使用可见但无 name 的 password 输入框，保留学校隐藏的 passwordEncrypt 字段和自己的提交处理；注入时发送 input、keyup、change、blur 事件。
- 大厅登录状态改为识别 ampHasLoginTool、ampHeaderToolUser 与 DIV 类型的“安全退出”控件，不再只找链接或按钮形式的退出入口。已在用户打开的实际服务大厅验证识别结果。
- 同一次跳转过程只处理一次认证成功，避免重复保存后再次导航；进入认证模块保留已有会话，主动切换账号时才清理统一认证会话。
- HTTP 认证跳转最多升级一次；同路径重复跳转（忽略时间戳和票据参数）及总跳转次数均有上限。失败状态保持停止，加载超过 45 秒显示重试提示；仅用户主动重试开始新一轮。
- 报修入口先访问大厅实际授权入口 appShow?appId=5341551514791165，落到后勤电脑版并完成加载后切换用户提供的移动版地址。在 Edge 中用户完成认证后，电脑版页面空白；同一会话打开移动版后已显示报修区域、项目、地址、故障描述、联系人及预约表单。未提交任何报修。

验证：75 项模拟表单检查（凭证为合成数据）、9 项大厅状态检查、32 项 URL 策略和 52 项导航/重复回调检查通过。实际 Edge DOM 和移动版表单已验证；尚未完成 Android 真机原生输入、验证码及 WebView 登录的端到端验收，桌面浏览器成功不等于手机端已验收。

## 1.6.0：统一身份认证与网上报修

- 用户页新增独立的统一身份认证模块：原生账号/密码表单、自动登录开关、最近认证记录和清除登录入口。教务与统一认证使用不同的 Android Keystore 别名、加密文件和设置文件。统一认证文件为 noBackupFilesDir/identity-login.enc，不包含在备份或安装包中。
- 首页新增主题色“网上报修”入口，内置打开用户提供的 http://hqfw.jhun.edu.cn/wsbx/html/yd/wsbx.html#/wybx，沿用手机内的校园服务会话。跳转到学校认证页后，可使用已保存的统一认证凭证；失败后停止自动重试，交由用户处理。
- 原生表单调用学校自己的登录按钮处理请求，保留学校的表单令牌与密码处理逻辑，不模拟或绕过验证码。普通验证码可在原生表单输入；额外验证可切换到学校页面。学校页面中手动输入的密码不会被应用读取，因此该方式只建立会话，不保存新凭证。
- 报修网页支持通过系统图片选择器附加图片；表单内容和提交均由用户操作。加载、连接失败、网页提示和重试入口使用应用主题。
- 修复教务登录/退出原先清空所有 Cookie 的行为。现在只清理对应域名及路径的会话与网页存储，分别管理教务与统一认证。凭证清除保留课表、成绩、自定义课程和背景。
- 仅服务大厅和后勤站点两个明确的域名允许 HTTP；统一认证密码只注入 HTTPS 的 authserver.jhun.edu.cn/authserver/login，并校验表单目标以及嵌套 service 回跳地址。认证页的 HTTP 跳转升级到 HTTPS，证书错误不会忽略。

验证：65 项模拟登录 DOM/凭证注入边界检查、32 项认证 URL 策略检查、202 项会话清理范围模拟检查通过；原有教务登录适配与 50 项课表/成绩查询解析检查通过。资源/Java/Dex 和 APK 签名检查通过，与 1.5.7 使用同一包名和签名，可覆盖安装。

1.6.0 发布时的接入限制（1.6.1 已补充实际浏览器验证）：当时工具无法连接用户的 Edge；直接读取统一认证页面被浏览工具安全策略拦截，服务大厅返回 403。实现依据用户提供的完整地址及通用表单结构，尚未用真实账号验证学校当前 DOM、CAS 跳转、验证码和报修页面。模拟检查不代表真实网站端到端登录成功，不能承诺报修站点没有额外授权步骤。

## 安装与使用

将 Sanjiaohu-1.6.0.apk 传到手机安装，可覆盖 1.5.7。与 1.5.6 及更早版本的包名不同，不能覆盖那些版本，也不会自动继承其数据。

首次打开可在首页添加自定义课程；用户页打开原生账号密码登录表单，登录后获取并保存教务课表。右上角 ⋮ →「周次校准」选择第一教学周的周一日期，以准确映射教学周与实际日期。

之后每次打开或返回前台，先展示缓存，再后台更新当前数据页面；打开成绩或汇总也会自动尝试更新。网络、登录或解析失败时保留该范围的上次记录。尚未登录、也没有已同步缓存时，只显示用户自己添加的自定义课程，不预装个人数据。

## 登录白屏的排查范围

本次独立访问学校登录入口也发生超时，手机端的实际登录仍待验证。学校官方公布的入口为 [教务系统首页](https://jwxt.jhun.edu.cn/)，可参见 [学校选课通知](https://jwzx.jhun.edu.cn/83/5f/c7525a230239/pagem.htm)。若 1.1 仍无法登录，页面会显示失败原因，可提供这段错误文字以继续定位。

## 数据与隐私

- 不预装课表、不复制电脑 Cookie、不记录明文密码。用户开启自动登录后，仅保存本机加密凭证。
- WebView 登录会话留在本机；课表、成绩、汇总 JSON 保存在应用私有目录，关闭系统云备份。汇总仅保存聚合指标，不额外保存整份入学以来成绩明细。
- 教务和地图仅允许学校 HTTPS 域名导航。统一认证使用 HTTPS，用户提供的服务大厅、后勤报修 HTTP 地址通过精确域名配置开放；不跳过证书验证。
- 缓存完整校验后通过 AtomicFile 原子替换；未验证范围的空结果或不完整响应不覆盖缓存。
- 新同步的缓存带有 source: school-sync 来源标记。
- 按学期保存 schedule-年-学期.json 与 grades-年-学期.json，入学以来汇总存于 summary-all.json；网络同步不修改 custom-courses.json。换账号时，在新账号成功同步前仍保留旧缓存。
